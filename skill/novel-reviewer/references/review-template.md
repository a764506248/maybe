# 审视记录模板

将记录追加到项目既有审视档案中。保留历史条目，不追改旧分数；若无档案，再创建独立记录文件。

```markdown
## 第 N 章审视记录

审视时间：YYYY年M月D日 HH:MM

### 本轮任务

一句话说明本章完成的功能、本轮审视范围和修改边界。

### 修改前评分

**X.X／100，结论。** 连贯性 X.X，逻辑可信度 X.X，剧情推动 X.X，节奏 X.X，吸引力 X.X，思想型暗黑风格 X.X。

### 关键问题

1. 场景或原句；造成的阅读后果；修改目标。
2. 最多三项。

### 最小修改方向

说明要删除、移动、补强或保留什么，以及哪些内容因未确认不能修改。

### 修改后复核

**X.X／100，结论，较修改前变化 X.X 分。**

| 核心项 | 分数 | 复核结果 |
| --- | ---: | --- |
| 连贯性 | X.X | 证据。 |
| 逻辑可信度 | X.X | 证据。 |
| 剧情推动合理性 | X.X | 证据。 |
| 节奏与拖沓度 | X.X | 证据。 |
| 吸引力 | X.X | 证据。 |
| 思想型暗黑风格 | X.X | 证据。 |

一句话说明下一章最重要的结构任务。
```

正文无需修改时，把“修改前评分”改为“评分”，并用下列结尾：

```markdown
### 复核结论

无需为制造评分变化而强行改字。说明正文为何已经成立，以及下一章应避免或处理什么。
```

## 跨章附加项

每五章追加：

- 本阶段整体分数与一句话功能链。
- 已解决问题和未解决问题。
- 主线比例、冲突类型、章末手法与时间线检查。
- 下一章唯一最重要的结构任务。

不要把完整的 14 项评分机械重复到每次记录；核心六项始终展示，其余项目只在决定结论或发现异常时展开。
